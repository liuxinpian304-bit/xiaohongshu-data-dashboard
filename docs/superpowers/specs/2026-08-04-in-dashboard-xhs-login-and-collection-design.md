# 驾驶舱内小红书登录与真实数据采集设计

## 目标

用户不离开数据驾驶舱即可完成小红书扫码登录，并在同一驾驶舱查询本人账号在小红书创作服务平台实际提供的笔记、指标和评论数据。登录及采集仅在用户本机运行，数据源固定为 `self-scrape`；现有 `mock` 演示和未来 `official` connector 保持不变。

## 已确认方案

采用方案 A：本机 Collector 持有持久 Chromium profile，驾驶舱只接收短时二维码图像、脱敏会话状态、同步进度和规范化业务数据。驾驶舱不嵌入第三方页面，不接收 Cookie、localStorage、浏览器 profile 或原始认证响应。

## 组件与职责

### Local Collector

- 只监听 `127.0.0.1`，要求高强度 Bearer token，并由功能开关显式启用。
- 使用 Playwright persistent context 打开 `https://creator.xiaohongshu.com/`。
- 在登录页定位二维码容器，只截取二维码区域；二维码图像短时保存在内存，响应设置 `no-store`，登录成功或过期后立即不可访问。
- 识别登录结果时仅返回 `awaiting_scan | authenticated | verification_required | expired | error` 等脱敏状态，不返回认证材料。
- 登录后进入创作中心可见的笔记管理、数据分析和评论页面，通过可见 DOM 及该浏览器会话已正常收到的响应提取本人账号数据。
- 不调用凭空猜测的私有 endpoint，不绕过验证码、风控、设备验证或访问控制；验证页面必须由用户亲自处理。

### API 与 BFF

- API 是唯一能够调用 Collector 的应用进程，Collector token 不进入浏览器、数据库或日志。
- Web 只能通过现有管理员 session、CSRF、Origin、Fetch Metadata 保护的 BFF 发起登录和同步动作。
- 二维码响应限制为 PNG、固定像素上限和字节上限；所有状态与错误使用固定允许值。
- 登录会话一次只允许一个；启动、轮询、确认、关闭和重新登录均幂等。

### 数据写入

- Collector 输出版本化 JSONL/事件，不直接写数据库。
- Worker 复用现有 `self-scrape` 导入 contract，将笔记写入 `Note`，将 `views/likes/comments` 写入 append-only `MetricSnapshot`。
- `views` 仅在创作中心明确提供时写入；否则保存 `not_provided + null`。
- 点赞、评论等累计值使用 `cumulative_delta`，`authoritativePeriod=false`，不伪造统计窗口。
- 每次同步拥有 run ID、文件 hash、成功/失败计数和脱敏审计；重复数据为 no-op，变化值追加 revision。

## 评论完整抓取

- 对每条笔记逐页或逐段加载一级评论，直到页面明确没有下一页。
- 对每条一级评论继续展开并加载全部回复，直到明确没有更多回复。
- 评论使用平台 ID 幂等写入，保留父子关系、正文、发布时间、点赞数和首次/最后发现时间。
- 每条笔记记录完整度：`partial | page_complete | failed | authorization_required | unverifiable`。
- 只有遍历到明确终点才能标记 `page_complete`；游标重复、页面结构变化、风控或超时不得冒充完整。

## 驾驶舱交互

账号页显示一个本机真实登录卡片：

1. 用户点击“在驾驶舱登录小红书”。
2. 页面显示真实、短时有效的二维码和倒计时。
3. 用户扫码后，页面自动切换到账号已连接状态。
4. 用户点击“立即同步”，或等待本机计划任务运行。
5. 页面显示当前阶段：账号、笔记、指标、评论、回复、写入、报表重建。
6. 同步完成后显示新增笔记数、指标修订数、评论数、不完整笔记数和最后同步时间。

移动端和桌面端都必须可操作；状态变化通过轮询实现，第一阶段不引入 WebSocket。

## 调度与报表

- 每日采集昨天至本月当前已结束日期的累计数据，并允许补采本月缺失日期。
- 周日生成包含前六天加当天所属统计范围的周汇总；具体日期边界继续复用现有 Asia/Shanghai 报表规则。
- 月末/次月首日完成上月最终汇总，并保留后到数据触发的 append-only report rebuild。
- 同步结束后通过现有通知模块提示成功、部分完成、登录失效或失败。

## 安全与隐私

- profile 目录权限 `0700`；二维码只在内存中短时存在。
- Cookie、localStorage、二维码原图、手机号、验证码和原始响应不得进入应用日志、审计、通知或 Git。
- API/网页不得提供任意 URL 导航、任意 selector、Cookie 导出或脚本执行接口。
- 采集只面向用户本人登录后可见的数据，不提供批量账号、绕过限制或第三方账号采集能力。
- 关闭会话保留 profile；清除登录状态必须是单独的危险操作并再次确认。

## 错误处理

- 二维码过期：自动生成新二维码，旧二维码立即失效。
- 需要验证：显示 `verification_required`，等待用户在受控验证界面亲自完成。
- 页面结构变化：停止对应阶段，保存已完成行级事务并将完整度标记为 `unverifiable`。
- Collector/API/数据库失败：写脱敏失败审计，不删除既有快照，不把部分评论标记完整。
- 登录失效：停止采集、禁用计划同步并通知重新扫码。

## 第一阶段验收

- 驾驶舱账号页内部显示真实小红书二维码，不要求用户切换到外部 Chrome 扫码页面。
- 扫码后驾驶舱显示 `authenticated`，且网页/API/数据库中均不存在 Cookie 或 localStorage。
- 能从本人创作中心同步至少一条真实笔记及其可见点赞、评论累计值。
- 能抓取该笔记全部可访问一级评论与回复，并给出可信完整度。
- 同一数据重跑不重复，变化数据追加 revision，报表只消费 `self-scrape`。
- mock 和 official 路径、现有 JSONL 离线导入均不回归。

## 非目标与真实限制

- 不承诺获得创作中心没有展示或没有返回的指标。
- 不把用户确认扫码当成登录验证，必须由 Collector 从创作中心登录后页面状态确认。
- 不实现云端多租户 Cookie 托管；第一阶段严格限于用户本机。
- 不自动处理 CAPTCHA、短信验证码或设备风险确认。
