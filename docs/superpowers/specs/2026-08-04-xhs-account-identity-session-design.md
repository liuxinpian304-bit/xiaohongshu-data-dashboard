# 小红书真实账号身份与持久会话设计

## 目标

驾驶舱账号页必须显示当前扫码登录的小红书真实账号，而不是 `local-creator` 等内部占位标识。首次扫码成功后长期复用登录会话；仅在会话失效、平台要求安全验证或用户主动切换账号时重新扫码。

本设计保留现有 mock 演示和未来官方 API connector，不重构 connector 接口。真实网页会话继续属于 `self-scrape` 数据源。

## 成功标准

- 账号卡片显示真实昵称、小红书号或稳定账号标识、头像、登录状态、最后核验时间和最后同步状态。
- 同一小红书账号再次登录时匹配原有 Account，不创建重复账号。
- 不同账号拥有独立会话和数据归属，任何一次同步都不能把数据写入另一个账号。
- 服务重启后可复用尚未失效的会话，不要求再次扫码。
- 会话失效时明确显示“需要重新扫码”，不能继续显示“已连接”。
- mock 与未来 official 账号仍可共存，现有 mock 行为保持不变。

## 方案

采用真实身份绑定方案。采集器在扫码成功后从已登录页面读取账号资料及平台稳定标识，API 使用 `(connectorType, platformId)` 唯一键匹配 Account，并把采集会话与该 Account 绑定。同步任务必须携带绑定后的 accountId，导入层继续校验笔记与账号归属。

仅修改显示名称会在切号后产生串号风险；手工绑定会把关键的数据归属判断交给人工。这两个方案不采用。

## 组件边界

### 本地采集器

- 管理多个账号各自独立的浏览器存储状态。
- 提供登录会话列表、创建扫码会话、身份核验、失效检测和指定账号采集能力。
- 扫码完成后返回经过校验的公开身份资料，不返回 Cookie、令牌或其他敏感凭据。
- 每次采集前重新核验平台身份；核验结果与目标账号不一致时停止任务并报告 `identity_mismatch`。

### API

- 将采集器身份映射为 `self-scrape` Account。
- 返回账号身份投影和会话状态供网页展示。
- 发起同步时必须指定已绑定且状态有效的账号。
- 记录登录、身份变化、会话失效和重新绑定的审计事件，但不记录敏感会话内容。

### 数据库

Account 继续以 `(connectorType, platformId)` 保证唯一性，并补充可空的头像地址和身份核验时间。会话元数据单独记录账号关系、状态、最后核验时间和密文存储引用；浏览器状态本身不直接暴露给业务查询。

会话状态为：

- `active`：身份已核验，可同步。
- `verification_required`：平台要求验证，需用户处理。
- `expired`：会话失效，需重新扫码。
- `identity_mismatch`：会话中的平台账号与绑定 Account 不一致，禁止同步。
- `unavailable`：采集器不可达，不能据此断定用户已退出。

### 网页

账号页按真实账号展示头像、昵称、小红书号、登录状态、最后核验时间和最后同步结果。每个账号分别提供“立即同步”和“重新扫码”。新增账号通过“添加小红书账号”创建新的独立扫码流程。

## 数据流

1. 用户选择添加账号，API 请求采集器创建一个隔离的登录会话。
2. 网页显示该会话的二维码并轮询状态。
3. 扫码成功后，采集器读取真实身份并返回稳定平台标识、昵称、小红书号和头像。
4. API 按稳定平台标识创建或更新 Account，并绑定会话。
5. 后续同步直接复用该账号会话；同步前执行静默身份核验。
6. 核验通过后采集笔记与评论，导入数据时使用绑定后的 accountId。
7. 核验失败则停止采集，更新明确状态并通知用户重新扫码或完成验证。

## 长期登录与安全

- 每个账号使用独立的持久化浏览器存储状态，避免 Cookie 相互覆盖。
- 会话文件以随机内部标识命名，禁止使用昵称或小红书号作为文件路径。
- 会话内容在静态存储时加密，密钥由运行环境注入，不提交 Git。
- API 和网页只接收状态与公开身份资料，不接收原始 Cookie。
- 日志、错误响应和审计详情必须过滤 Cookie、localStorage、令牌及二维码内容。
- 删除账号时先停用会话；业务历史数据是否保留沿用现有账号删除规则。

## 错误处理

- 采集器不可达时显示“采集服务不可用”，保留最后一次已核验身份，不误报为退出登录。
- 身份不一致时禁止自动改绑旧 Account，要求以新的平台标识匹配或创建账号。
- 昵称或头像变化只更新展示资料，不改变数据归属。
- 平台页面结构变化导致身份字段无法读取时停止同步，不能回退到 `local-creator`。
- 同一账号存在并发登录或同步请求时，以账号为粒度串行化，防止会话状态竞争。

## 测试与验收

- 单元测试：身份解析、状态映射、敏感字段过滤和账号投影。
- 集成测试：同账号幂等绑定、不同账号隔离、身份不一致拒绝、失效状态持久化。
- API 测试：账号列表返回真实身份与会话状态，指定账号同步不会跨账号。
- 网页测试：真实信息渲染、失效提示、重新扫码入口和多账号操作互不影响。
- 浏览器验收：首次扫码后显示真实账号；刷新和服务重启后仍保持登录；连续切换两个测试账号时数据不串号；人为清除会话后正确提示重新扫码。

## 实施范围

本轮先完成真实身份准确显示、单账号会话持久化和严格归属校验，这是多账号安全运行的基础。随后在相同模型上增加多个并存会话和账号切换，不改变数据模型的核心约束。
