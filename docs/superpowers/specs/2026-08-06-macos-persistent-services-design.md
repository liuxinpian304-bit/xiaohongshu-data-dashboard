# macOS 固定后台服务设计

## 目标

将小红书数据驾驶舱从依赖临时终端的开发进程，改为当前 Mac 用户登录后自动启动、异常退出后自动恢复的本地后台服务。用户访问 `http://127.0.0.1:3000` 时，不再因为 Codex 任务结束或终端关闭而出现“无服务”。

## 选定方案

使用 macOS `launchd` 管理网页、API 和本地扫码采集器。PostgreSQL 与 Redis 继续运行在现有 Docker Compose 容器中，并配置 Docker 重启策略。该方案保留扫码采集器对本机 Chrome 和持久化浏览器配置目录的访问，避免将浏览器自动化迁入容器。

## 组成

### 本机私有运行环境

在用户级应用支持目录保存一个不进入 Git 的环境文件，包含数据库连接、管理员密码哈希、凭据加密密钥和采集器令牌。文件权限限制为当前用户可读写。仓库只保存无秘密的示例和启动逻辑。

### 启动包装器

仓库提供统一包装脚本，为三个服务设置固定工作目录、项目自带 Node/pnpm 路径和私有环境变量。脚本支持：

- `install`：安装并加载用户级 LaunchAgent。
- `start`：启动数据库依赖和三个应用服务。
- `stop`：停止应用服务。
- `restart`：重启全部应用服务。
- `status`：检查容器、端口和 HTTP 健康状态。
- `uninstall`：卸载 LaunchAgent，但不删除数据库数据。

### LaunchAgent

使用三个独立的用户级 LaunchAgent：

- Web：监听 `127.0.0.1:3000`。
- API：监听 `127.0.0.1:3001`。
- Collector：仅监听回环地址 `127.0.0.1:43127`。

每个服务启用登录自动启动和异常退出自动拉起，并将标准输出与错误输出写入用户级日志目录。服务彼此独立，单个进程重启不会强制中断其他进程。

## 启动和数据流

安装时先确认 Docker、数据库容器和 Redis 容器可用，然后写入私有配置并加载 LaunchAgent。Web 通过本机 API 获取数据；API 使用最小权限数据库账号访问 PostgreSQL，并通过固定令牌调用 Collector；Collector 使用已有持久化 Chrome 配置目录保存小红书登录会话。

若数据库暂时未就绪，API 退出，由 `launchd` 延时重试。若 Collector 尚未登录小红书，它保持 `idle` 或待登录状态，但 API 和网页仍可访问历史数据。

## 安全约束

- Collector 只绑定 `127.0.0.1`，不向局域网开放。
- 私有配置与日志不提交 Git。
- 环境文件权限为 `0600`，LaunchAgent 配置不直接包含明文秘密。
- 不改变现有管理员登录、账号数据模型或 connector 接口。
- 卸载操作不删除 PostgreSQL 数据卷、扫码登录配置或业务数据。

## 故障处理

- 进程异常退出：`launchd` 自动重新启动并记录日志。
- Docker 未运行：状态命令明确报告依赖不可用；启动命令尝试启动现有 Compose 服务。
- 端口被占用：安装或启动前检查占用者，拒绝覆盖未知进程。
- 配置缺失或权限过宽：服务拒绝启动，并在状态输出中给出修复提示。
- Collector 未登录：网页继续展示历史数据，账号页提示重新扫码，不将其误报为整个系统离线。

## 验收

1. PostgreSQL、Redis、Web、API、Collector 均能通过统一状态检查。
2. Web、API、Collector 分别返回预期 HTTP 状态。
3. 结束任一应用进程后，`launchd` 能自动拉起新进程。
4. 关闭当前终端或结束 Codex 任务后，网页仍可访问。
5. 重新加载 LaunchAgent 后，历史数据库和 Collector 浏览器配置保持不变。
6. 安装产生的仓库文件通过 shell 语法检查，且不会把秘密加入 Git。

## 非目标

- 本阶段不部署公网服务器。
- 不把扫码采集器容器化。
- 不修改现有看板功能、报表算法或数据导入格式。
- 不承诺在 Mac 完全关机或未登录用户时提供服务。
