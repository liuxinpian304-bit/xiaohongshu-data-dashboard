# 多账号横向登录卡片设计

## 目标

把账号页顶部现有的大块单账号登录面板改为一排多账号卡片，让已登录账号一眼可见，并让每个账号在头像下方保留独立的“立即同步”按钮。

## 页面结构

### 已登录账号区

- 区域标题为“已登录账号”。
- 每个真实小红书账号显示为一张独立卡片。
- 桌面端横向排列，空间不足时自动换行。
- 手机端每行显示一张卡片。
- 不把 mock 演示账号或未来的 official connector 混入真实登录账号卡片。

### 账号卡片

每张卡片从上到下显示：

1. 圆形账号头像；没有头像时显示昵称首字。
2. 账号昵称。
3. 小红书号；缺少小红书号时显示稳定平台标识。
4. 登录状态：登录有效、需要重新登录或状态待确认。
5. 位于头像信息下方的“立即同步”按钮。

同步按钮只同步当前卡片代表的账号。同步过程中仅禁用当前账号的按钮，并在卡片内显示笔记、指标、评论、回复、写入、报表重建等中文进度。

### 登录新账号卡片

- 账号列表末尾固定显示“＋ 登录新账号”卡片。
- 点击后在卡片区域下方展开扫码登录面板。
- 二维码、平台验证、错误和过期状态继续复用现有本地采集器安全流程。
- 登录成功后收起二维码，并刷新账号卡片列表。

## 多账号行为

- 数据库中的每个 `self-scrape` 账号独立显示。
- 采集器一次只维护一个当前登录会话；“立即同步”前必须核验当前会话身份与目标账号一致。
- 如果当前会话不是该卡片账号，按钮显示“登录此账号后同步”，点击后进入扫码/身份核验流程，不允许把另一个账号的数据写入当前账号。
- 当前会话与目标账号一致时，按钮显示“立即同步”。

## 保留内容

- 下方“演示连接器”“自有数据导入”“官方 API”三块能力说明保持不变。
- 现有账号管理列表继续保留，用于账号资料、来源状态和账号生命周期操作。
- 官方 API 入口继续保留，不伪装为可用能力。

## 安全与错误处理

- 不在网页或数据库保存扫码凭据、Cookie 或本地采集器令牌。
- 同步前继续进行稳定账号身份核验。
- 一个账号同步失败不会影响其他账号卡片。
- 账号、API 或采集器不可用时显示中文错误，不让整个账号页崩溃。

## 验收标准

- 桌面端顶部显示横向账号卡片，账号多时自动换行。
- 每个真实账号头像下方都有独立同步按钮。
- 每个按钮只允许同步身份匹配的账号。
- 列表末尾有“登录新账号”卡片，点击后可展开扫码流程。
- 手机端卡片单列显示。
- 下方三类连接器区域和账号管理列表仍然存在。
- 组件测试、API 测试、类型检查和浏览器验收通过。
