# 局域网访问驾驶舱设计

## 目标

让同一局域网内的手机、平板和其他电脑通过宿主 Mac 的局域网地址访问数据驾驶舱，同时只对外开放 Web 端口，继续将 API、数据库、Redis 和小红书采集器限制在本机。

当前宿主机局域网地址为 `192.168.0.7`，目标访问地址为 `http://192.168.0.7:3000`。局域网地址可能在路由器重新分配后变化，因此服务状态命令必须显示当前可用地址，不能把 `192.168.0.7` 当作永久固定配置。

## 网络边界

- Next.js Web 服务监听 `0.0.0.0:3000`，允许同一局域网设备连接。
- NestJS API 继续只监听 `127.0.0.1:3001`。
- 本地小红书采集器继续只监听 `127.0.0.1:43127`，并保留 bearer token 校验和 loopback 强制检查。
- PostgreSQL 和 Redis 不新增局域网暴露；Docker 映射维持现状，不为其他设备提供应用级入口。
- 局域网设备只与 Web/BFF 通信，由 Web 服务在宿主机内部调用 API 和采集器。

## 同源与登录安全

Web BFF 接受两类明确允许的来源：本机 `http://127.0.0.1:3000`，以及启动时检测到的当前局域网地址（例如 `http://192.168.0.7:3000`）。不接受任意 `Host`、跨站来源、不同端口或公网来源。

允许来源通过 `APP_ORIGINS` 逗号分隔配置传入。Web 端验证浏览器请求的 `Origin` 必须存在于允许列表，并将已验证的原始来源转发给 API。API 的登录、鉴权守卫和写操作同样使用相同允许列表。旧的单值 `APP_ORIGIN` 保留为兼容回退，避免其他部署方式失效。

管理员密码和会话机制保持不变。局域网使用 HTTP 时 cookie 不设置 `Secure`，但仍保持 `HttpOnly`、`SameSite`、CSRF token、同源检查和登录限速。密码不会写入页面、URL、日志或浏览器持久存储。

## 固定服务配置

`ops/macos/xhs-services.sh` 在安装和启动时检测活动的私有 IPv4 地址。优先使用 Wi-Fi 接口地址；只接受 RFC1918 私有网段，检测不到时仅启用本机来源并在状态输出中标记“局域网地址不可用”。

Web 服务改为 `next dev --hostname 0.0.0.0`。运行环境设置：

```text
APP_ORIGINS=http://127.0.0.1:3000,http://<当前私有IPv4>:3000
API_BASE_URL=http://127.0.0.1:3001
```

API 与 collector 的监听地址和内部 URL 不变。服务脚本的 `status` 输出新增 `lan_url=http://<当前私有IPv4>:3000`，方便用户从其他设备直接输入；检测不到地址时输出 `lan_url=unavailable`。

## 防火墙与可达性

不自动关闭 macOS 防火墙，也不修改路由器。部署后先从宿主机使用局域网 IP 请求 Web，证明服务确实监听外部接口；再提示用户在同一 Wi-Fi 的第二台设备打开状态命令给出的地址。

如果 macOS 弹出“是否允许传入连接”，用户只需允许 Node/Web 服务。任何要求开放 `3001`、`43127`、`5432/55432` 或 Redis 端口的方案都视为验收失败。

## 测试策略

- 单元测试：允许来源解析会去重、拒绝无效 URL、拒绝不同端口和未知来源，同时兼容旧 `APP_ORIGIN`。
- Web BFF 测试：本机来源和配置的局域网来源可执行写操作；恶意或未配置来源继续返回拒绝。
- API 测试：登录控制器和鉴权守卫接受允许列表中的局域网来源，拒绝列表外来源。
- 服务脚本测试：Web 使用 `0.0.0.0`，API/collector 保持回环，状态输出包含 `lan_url`。
- 部署验收：`127.0.0.1:3000` 与当前私有 IP 的 `:3000` 均返回驾驶舱；`192.168.0.7:3001` 和 `192.168.0.7:43127` 不可连接。
- 浏览器验收：通过局域网 URL 登录，打开账号和总览页面，验证无框架错误、无控制台错误，并测试一个不改变业务数据的导航交互。

## 错误处理

- 没有私有 IPv4：服务仍可通过 `127.0.0.1` 使用，状态明确显示局域网不可用。
- IP 地址变化：重新运行固定服务安装命令刷新 `APP_ORIGINS` 和显示地址。
- 局域网设备打不开但宿主机局域网地址可访问：判定为 macOS 防火墙、访客 Wi-Fi 隔离或路由器客户端隔离问题，不扩大内部服务监听范围。
- 局域网登录返回来源拒绝：检查状态显示地址与浏览器地址是否一致，重新安装服务刷新允许来源。

## 验收标准

1. 宿主机本地地址和当前局域网地址都能打开并登录驾驶舱。
2. 其他同网设备能通过状态输出的 `lan_url` 使用驾驶舱。
3. 只有 Web 的 `3000` 端口对局域网可达；API、collector、PostgreSQL 和 Redis仍不可达。
4. 所有写操作继续受管理员会话、CSRF、允许来源和登录限速保护。
5. 局域网 IP 变化后可通过重新安装服务自动刷新，无需修改代码。
