# 抖音多平台驾驶舱设计

日期：2026-08-10
状态：用户已确认交互设计，等待书面规格复核

## 1. 目标

在不破坏现有小红书账号、作品、指标、评论、报表和数据来源的前提下，将驾驶舱扩展为小红书与抖音共用的多平台管理后台。

首期通过小火花中已经登录的抖音账号读取真实数据。同时保留离线 JSON 导入入口和未来抖音官方开放平台 API 入口。抖音首期覆盖多账号、作品、播放量、点赞、评论、收藏、分享、粉丝变化、全部一级评论及全部回复。

## 2. 已确认的产品范围

### 2.1 数据入口

系统保留三种抖音数据入口：

1. `xiaohuohua`：首期真实数据入口，从小火花中的已登录抖音账号读取。
2. `self-import`：接收用户自抓 JSON，用于离线导入、补数和迁移。
3. `official`：保留抖音官方 API 适配器边界，获得审批后启用。

数据入口是来源，不是平台。系统必须分别保存 `platform` 与 `source`，不得继续通过一个 `connectorType` 同时表达二者。

### 2.2 抖音首期指标

账号级数据：

- 头像、昵称、抖音号、登录状态
- 粉丝总量和粉丝变化

作品级数据：

- 播放量
- 点赞数
- 评论数
- 收藏数
- 分享数

评论级数据：

- 每条一级评论
- 每条评论下的全部回复
- 评论作者、正文、发布时间、点赞数和父评论关系（平台可提供时）
- 评论分页完整性状态

平台未提供的字段必须表示为“暂无数据”，不能使用 `0` 代替未知值。

### 2.3 多账号管理

- 支持任意数量的抖音账号。
- 每个账号展示头像、昵称、抖音号、平台、登录状态和最近同步时间。
- 每个账号保留独立的“立即同步”按钮。
- 单个账号登录失效不影响其他抖音账号或小红书账号。
- 小火花中新增加的抖音账号可以被发现并导入驾驶舱。

## 3. 页面与交互

采用“全平台混合总览”布局。

### 3.1 全平台总览

- 首页同时展示小红书与抖音的账号和内容表现。
- 平台卡片使用各自名称和清晰的视觉标识。
- 允许按全部平台、小红书、抖音以及单个账号筛选。
- 不把语义不同的指标直接相加。例如“小红书阅读量”和“抖音播放量”分别展示。
- 跨平台汇总只使用已定义为同义且口径兼容的指标，例如经过统一定义的互动量。

### 3.2 账号、作品、评论与报告

- 账号页支持平台筛选并展示账号同步状态。
- 现有“笔记”概念在用户界面统一改为“作品”，小红书内容可继续标注为“笔记”，抖音内容标注为“视频/图文”。
- 作品列表和详情页显示平台徽标，并展示该平台实际支持的指标。
- 评论页支持平台、账号和作品筛选，展示一级评论与回复层级。
- 导出功能支持导出当前筛选范围，并在导出文件中包含平台、来源、账号和抓取时间。

## 4. 架构

采用统一多平台数据层，不为抖音复制一套独立业务表。

```text
小火花 / JSON / 官方 API
          |
          v
平台适配层（小红书适配器、抖音适配器）
          |
          v
校验、去重、字段映射、完整性判定
          |
          v
统一数据层（平台、账号、内容、指标、评论、同步运行）
          |
          +--> 日报 / 周报 / 月报
          +--> 全平台驾驶舱与导出
```

### 4.1 边界

- `platform` 表示数据所属平台，首期允许 `xiaohongshu`、`douyin`。
- `source` 表示观测来源，允许 `xiaohuohua`、`self-import`、`official`，现有来源值通过兼容映射保留。
- 平台适配器只负责读取平台数据并输出标准采集事件。
- 导入服务负责校验、事务写入、幂等和完整性状态。
- 报表引擎只读取统一模型，不依赖小火花页面结构。
- 页面只通过 API 访问统一模型，不直接调用小火花或平台接口。

### 4.2 兼容迁移

- 现有小红书账号、笔记、评论、指标和报表补充 `platform=xiaohongshu`。
- 现有 `mock` 演示路径、`self-scrape` 离线导入和 `official` 入口保持可用。
- 不删除现有数据，不重新生成现有业务主键。
- API 在迁移期兼容现有字段；新增响应包含明确的 `platform` 与 `source`。
- 报表逻辑中对 `official`、`mock`、`self-scrape` 的硬编码改为平台无关的来源策略。

## 5. 标准数据模型

### 5.1 平台账号

账号唯一性为 `(platform, platformAccountId)`。账号包含显示名称、头像、账号标识、身份校验时间、登录状态、最近同步时间和可用能力。

### 5.2 内容

内容唯一性为 `(platform, platformContentId)`。内容包含账号、内容类型、标题或摘要、发布时间、最近发现时间和来源。

### 5.3 指标观测

每次同步写入带抓取时间的累计指标观测。指标定义包含平台适用范围、单位、聚合方式、版本和有效期。抖音首期定义 `views`、`likes`、`comments`、`favorites`、`shares`，账号级粉丝指标单独定义。

### 5.4 评论

评论唯一性为 `(platform, platformCommentId)`，并保存内容平台 ID、父评论平台 ID、作者、正文、发布时间、点赞数、来源和抓取时间。回复通过父评论关系组织，不复制正文。

### 5.5 评论完整性

每个账号、作品和同步运行记录评论完整性：

- `complete`：已读取全部分页和全部可展开回复。
- `partial`：只读取部分评论或回复。
- `failed`：读取失败。
- `not_available`：平台或当前入口不提供评论。

只有明确到达平台分页末尾，并且全部回复已展开完成时，才能写入 `complete`。

## 6. 同步和报表数据流

1. 同步任务锁定单个平台和单个账号。
2. 适配器读取并验证账号身份。
3. 日常同步窗口为当月 1 日零时至业务日结束，读取本月作品。
4. 对每篇作品读取累计指标，并逐页读取全部一级评论及回复。
5. 标准事件经过校验和幂等写入后生成变更记录。
6. 报表引擎重新计算受到变更影响的日报、周报和月报。
7. 每月 1 日额外执行上月整月最终同步，生成并锁定上月月报。

平时不得主动读取上个月作品；只有每月 1 日的 `previous_month_final` 模式可以读取上个月整月数据。

## 7. 时间和聚合规则

- 业务时区固定为 `Asia/Shanghai`。
- 日报展示本月 1 日到当天的每一天，而不是只有当天。
- 周报保留现有周范围，并按每天的观测计算。
- 月报是独立报表，不取代每日明细。
- 累计指标通过相邻观测差值计算期间增量；缺少基线时标记不完整，不猜测数值。
- 平台指标定义与来源版本必须参与聚合选择，禁止混用不同来源的累计序列。

## 8. 异常处理与提醒

- 登录失效：暂停该账号，标记需重新登录并生成通知。
- 网络错误或小火花页面异常：指数退避重试；达到上限后记录失败阶段并通知。
- 平台限流：保留已提交的数据，将任务标记为部分完成，并延后重试。
- 评论未完成：保存已读取评论但标记 `partial`，页面明确提示不完整。
- 字段缺失：保存不可用状态，不写假 `0`。
- 单账号失败：不回滚其他账号已经成功提交的数据。
- 所有同步运行保存平台、来源、账号、时间窗口、阶段、计数、错误和重试次数。

## 9. 安全与凭据

- 驾驶舱不读取、导出或展示小火花及抖音的密码、Cookie、令牌或二维码凭据。
- 小火花会话保留在本机小火花应用中；适配器只操作用户已授权的本机会话。
- 官方 API 凭据继续使用现有加密凭据边界保存。
- JSON 导入先执行大小、格式、平台和账号归属校验，再进入事务写入。

## 10. 测试策略

### 10.1 数据层

- 平台与来源分离迁移测试。
- 不同平台相同平台 ID 不冲突测试。
- 同平台账号、作品、评论幂等测试。
- 指标不可用状态、版本和聚合口径测试。
- 评论完整、部分和失败状态测试。

### 10.2 同步与报表

- 多账号隔离和并发锁测试。
- 当月每日同步窗口测试。
- 每月 1 日上月最终同步测试。
- 普通日期禁止读取上月数据测试。
- 累计指标差值、缺少基线和来源隔离测试。
- 登录失效、限流、网络失败和重试测试。

### 10.3 API 与页面

- 全平台、平台和账号筛选测试。
- 作品指标、评论层级和完整性提示测试。
- 导出文件的平台、来源和筛选范围测试。
- 桌面端和移动端登录、总览、账号、作品、评论与报告冒烟测试。
- 现有小红书 mock、自抓 JSON、官方入口和历史报表回归测试。

## 11. 首期验收标准

1. 小火花中至少一个已登录抖音账号可导入并显示在账号页。
2. 账号头像、昵称、抖音号和登录状态准确。
3. 本月已发布作品按发布时间倒序显示，定时未发布作品不进入正式数据。
4. 每篇作品正确显示播放、点赞、评论、收藏和分享；未知值不显示为零。
5. 评论详情能逐条显示一级评论与回复，并展示可靠的完整性状态。
6. 全平台总览同时展示小红书和抖音，并能按平台与账号筛选。
7. 日报、周报、月报遵循本规格的时间窗口，普通日期不抓上月数据。
8. 当前筛选范围可以一键导出。
9. 单个抖音账号失败不会影响其他账号或小红书。
10. 现有小红书数据、mock 演示、离线导入和官方 API 保留入口均通过回归测试。

## 12. 非目标

首期不包含：

- 抖音直播数据。
- 抖音商品、橱窗、订单或带货数据。
- 自动发布、删除或修改抖音作品。
- 自动回复、点赞或管理平台评论。
- 绕过验证码、设备校验、风控或平台访问限制。
