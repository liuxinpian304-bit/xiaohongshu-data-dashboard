# 抖音真实扫码登录与同步设计

## 背景

当前实现只从小火花可见界面读取到一个账号名称，并将其显示为“抖音账号”。这不是经过身份核验的抖音登录会话，也不能证明采集器能够访问该账号的创作者后台数据。未经核验的可见名称不得继续显示为“登录有效”，也不得进入同步和报表链路。

本规格替代 `2026-08-10-douyin-multiplatform-dashboard-design.md` 中“首期依赖小火花登录状态”的登录与采集部分。统一多平台数据模型、离线导入和未来官方 API 边界保持不变。

## 目标与验收标准

1. 用户在驾驶舱账号页点击“登录抖音”，打开抖音创作者中心的真实登录窗口并使用抖音 App 扫码。
2. 登录成功后，采集器必须从抖音创作者后台返回中核验稳定账号 ID、昵称、抖音号和头像；核验前不创建正式账号记录。
3. 登录会话保存在本机独立、权限受限的浏览器配置目录中，重启电脑后可恢复；Cookie、令牌和密码不写入业务数据库或日志。
4. 每个抖音账号使用隔离的会话目录，允许连接多个账号；单个会话失效不影响其他账号。
5. 账号卡片显示真实身份、登录状态、最近核验时间、最近同步时间和“立即同步”按钮。
6. 同步从已核验的抖音会话读取创作者后台可见的作品、播放、点赞、评论、收藏、分享、全部一级评论和可访问的全部回复，并写入现有多平台数据模型。
7. 登录过期、验证码、安全验证、页面结构变化或数据分页不完整时必须显式失败并提示重新登录，不能沿用旧登录状态或把缺失值写成零。
8. 删除当前未核验的“抖音账号”假占位；历史数据可保留，但不能继续标记为已登录。

## 方案比较

### A. 独立持久化浏览器会话（采用）

由本机采集器启动抖音创作者中心的独立 Chrome 会话，用户在官方页面扫码，采集器只读取登录后的后台响应。优点是身份来源真实、会话可隔离、数据链路可测试，也不依赖小火花内部实现；缺点是抖音页面变化时需要维护适配器。

### B. 继续控制小火花

复用小火花已登录账号并从其界面读取数据。优点是扫码入口已有；缺点是目前只能确认可见名称，无法可靠取得稳定身份、完整分页和会话控制，也无法证明“登录有效”。不采用。

### C. 仅使用抖音官方 API

安全性和稳定性最好，但当前没有审批和凭据，无法满足立即使用。保留连接器边界，审批通过后可作为优先数据源。

## 架构

### 抖音会话管理器

在本机 collector 中新增与小红书会话管理器并列的 `DouyinSessionManager`。每个会话拥有随机内部 ID、独立浏览器目录和明确状态：`idle`、`launching`、`awaiting_scan`、`authenticated`、`verification_required`、`expired`、`error`、`closed`。

浏览器直接访问抖音创作者中心官方域名。驾驶舱不嵌入第三方登录页，只展示由本机采集器截取的当前二维码；扫码和安全验证仍在官方窗口完成。

### 身份核验

`DouyinPageAdapter` 仅接受白名单官方域名和有界 JSON 响应。登录成功后从创作者后台身份接口读取稳定账号 ID，再读取昵称、抖音号和头像。账号写入使用 `platform=douyin`、`source=self-scrape`、`connectorType=douyin-local`，并记录 `identityVerifiedAt`。

显示昵称或窗口标题不能作为身份依据。稳定 ID 缺失、身份前后变化或选定账号与当前会话不一致时，流程立即失败。

### 多账号隔离

账号页可创建新抖音登录会话，也可恢复已有会话。目录按内部会话 ID 隔离，映射文件仅保存会话 ID 与稳定账号 ID，不保存 Cookie 内容。删除账号连接时关闭该会话；是否删除本地会话目录必须由用户明确确认。

### 同步链路

同步前重新核验当前身份。采集器按作品列表、作品指标、评论和回复的顺序分页读取，产生现有 `PlatformCollectionEventV2`，固定 `platform=douyin`、`source=self-scrape`。API/worker 继续复用现有导入、快照、完整性和通知逻辑。

分页必须检测平台结束标志、重复游标、页数上限和超时。只有明确到达平台结束才标记 `page_complete`；其他情况写入不完整原因并发送通知。

## 页面与接口

账号页用新的“抖音真实登录”区域替换 `DouyinAccountDiscovery`：

- “登录新的抖音账号”按钮；
- 同源二维码图片和倒计时；
- 登录进度、安全验证和失效提示；
- 已连接账号卡片及“立即同步”“重新登录”按钮；
- 未核验的小火花可见名称不再展示为账号。

collector 提供账号作用域的会话创建、状态、二维码、关闭和采集接口；API 作为唯一 BFF 转发入口，校验管理员会话、CSRF、账号归属和响应结构。Web 浏览器不能直接访问 collector 端口。

## 安全约束

- collector 继续只监听 `127.0.0.1` 并要求高熵 bearer token。
- 会话目录权限为 `0700`，映射文件为 `0600`。
- 不读取用户输入的密码，不导出 Cookie，不记录二维码内容、响应令牌或请求头。
- 只允许抖音官方创作者域名；重定向到非白名单域名时停止。
- API 和 Web 保留同源、CSRF、响应大小与字段白名单校验。
- 本功能只管理用户自行登录并有权访问的账号，不绕过验证码、安全验证或访问控制。

## 错误处理

- 二维码过期：生成新二维码并要求重新扫码。
- 安全验证：保持窗口可见，提示用户在官方页面完成；不自动绕过。
- 会话过期：账号显示“需要重新登录”，同步任务不启动。
- 身份不匹配：关闭本次同步并提示选择正确账号。
- 页面变化或分页不完整：任务失败或标记不完整，保留上一轮已验证数据，不伪造新快照。
- 单账号失败：不影响其他抖音或小红书账号。

## 测试与上线

1. 会话状态机、二维码生命周期、域名白名单、目录权限和身份不匹配单元测试。
2. 使用脱敏固定响应测试账号、作品、指标、评论及回复解析，禁止提交真实 Cookie 或令牌。
3. collector、API BFF、数据库导入和账号页交互集成测试。
4. 测试数据库与正式数据库完全隔离，测试不得清空正式账号。
5. 本机人工验收必须完成一次真实扫码、身份显示、服务重启后的会话恢复和一次真实同步。
6. 上线前删除数据库中未经核验的抖音假占位；推送 Git 后部署固定后台服务。

## 非目标

- 不自动绕过验证码、短信验证或风控。
- 不发布、删除或修改抖音作品。
- 不抓取当前登录账号无权访问的数据。
- 不将页面可见名称当成真实授权。
- 本阶段不实现直播、电商、订单和带货数据。
